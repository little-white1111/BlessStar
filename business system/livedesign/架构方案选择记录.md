### 1.2 BlessStar 的角色

**BlessStar 仅作为配置驱动引擎**，不介入 livedesign 的业务逻辑：

```
config-schema.yaml  ← livedesign 的"配置宪法"
      ↓
blessstar-codegen --lang ts  → 生成 Port-Adapter 代码
      ↓
gate_rule_def.json  → 门禁规则（RANGE / APPROVAL / SLO_WARNING）
      ↓
adapter 层三阶段降级 → ConfigReader → CachedReader → provideBlessStarAdapters
```

livedesign 在 `initialize()` 中通过 3 行代码集成 BlessStar：

```typescript
const storeReader = new StoreConfigReader(configStore);
const cachedReader = new CachedReader(storeReader, 30_000);
adapters = provideBlessStarAdapters(cachedReader);
```

## 三、三方案对比

| 维度 | 方案A (增量增强) | 方案B (均衡融合) ⬅️ 推荐 | 方案C (全面重构) |
|:-----|:-----------------|:-------------------------|:-----------------|
| **核心思路** | 在现有聊天流程上增量添加情感/记忆模块 | Agent 编排器包装 LLM Service，深度融合人格模型 | 以 Actor 模型重写整个 LLM Service |
| **Personality** | 简单情感标签 + EmotionInferrer 增强 | VAD 三轴模型 + 人格特质 + 情感衰减 | OCEAN 五因子 + 完整心理模型 |
| **Memory** | 对话历史(SQLite) + 情感标签 | 工作记忆 + 情节记忆(SQLite) + 情感共鸣检索 | 工作/情节/语义/程序四层记忆 |
| **Live2D/TTS** | 完成 Cubism SDK 集成 + Web Speech TTS | Cubism SDK + 情感驱动 TTS (语调/语速) | Rust 原生高性能 Live2D + 流式 TTS |
| **Agent 架构** | 在 llm-service/index.ts 中增加函数 | AgentOrchestrator 独立管线 | 全新 Agent 运行时 (Actor 模型) |
| **STT** | 不实现 (保留文本) | Web Speech API 语音输入 | 完整 STT + 屏幕共享 + 事件感知 |
| **侵入性** | 低 — 不改动现有 IPC/进程架构 | 中 — 重构 LLM Service 为 Agent 管线 | 高 — 可能影响进程模型 |
| **预估工期** | 4-5 周 (1 人) | 8-10 周 (1-2 人) | 14-18 周 (2-3 人) |
| **配置扩展点** | +3 个 (情感衰减/记忆开关) | +8 个 (完整 personality/memory/output) | +15 个 |
| **维护成本** | 低 (增量) | 中 (边界清晰) | 高 |
| **BlessStar 影响** | 无 (不新增 schema 字段) | config-schema.yaml 扩展 + 代码重生成 | config-schema.yaml 大幅扩展 |

### 新增不变量 (NeuroSama 融合)

| # | 不变量 | 说明 |
|:-|:-------|:------|
| **A1** | **人格引擎是情感系统的唯一真理源** | 所有情感数值的变更必须经过 `PersonalityEngine` 的 trait 约束。`EmotionInferrer` 的输出必须经 PersonlityEngine 过滤后，才能分发给 Live2D/TTS/Expresser |
| **A2** | **情感衰减不可跳过** | `PersonalityEngine.decay` 以固定间隔 (默认 5 分钟) 运行。即使无用户输入，VAD 值也应自然回归基线 |
| **A3** | **情节记忆写入必须携带情感标签** | `EpisodicMemory.store()` 接口要求 emotion 参数非空。无情感标签的事件不写入情节记忆 |
| **A4** | **工作记忆容量上限 = 5 轮对话 + 3 个工具结果** | `WorkingMemory.push()` 超限时自动淘汰最旧条目，防止 Token 膨胀。此容量通过 config-schema 配置 |
| **A5** | **Agent 管线是 LLM Service 的唯一响应路径** | 禁止绕过 Agent 管线直接调用 LLM API。所有用户请求必须经过 Perceptor → Cognitive → Planner → Executor → Expresser |
| **A6** | **输出层情感状态必须与引擎 VAD 同步** | Live2D 表情参数和 TTS 语速/语调必须每秒与 `PersonalityEngine.getAffective()` 同步 |
| **A7** | **多模态输入归一化为统一 InputEvent** | 所有输入源 (文本/语音/系统事件) 必须转换为 `InputEvent { type, payload, timestamp }` 格式后进入管线 |

## 一、上下文与现状分析

### 1.1 当前 VAD 实现快照

| 维度 | 实现 | 文件 | 行数 |
|:-----|:-----|:-----|:-----|
| VAD 模型 | 22 个离散情绪点 + 欧氏最近邻匹配 | `personality/affective.ts` | 81 |
| 人格特质 | 2 个（playfulness/empathy）线性增益 0.5×~1.5× | `personality/traits.ts` | 45 |
| 情感衰减 | 确定性指数回归基线，无噪声 | `personality/decay.ts` | 89 |

### 1.2 已诊断的架构问题

**问题 1：VAD 空间覆盖严重不足**

```
VAD [0,1]³ 单位立方体总体积: 1.0
22 个离散点有效覆盖体积: ≈ 0.158（每个点球半径 0.12）
真空区占比: ≈ 84%

最严重真空区:
  - 冷静恶意 (0.15, 0.20, 0.85) → 最近 sad 距离 0.558 ❌
  - 狂热迷恋 (0.85, 0.80, 0.20) → 最近 excited 距离 0.539 ❌
  - 傲慢满足 (0.95, 0.10, 0.85) → 最近 relaxed 距离 0.484 ❌
```

**问题 2：感知端无渐变分辨率**

```typescript
// perceptor.ts — 任何匹配都返回固定 intensity: 0.3
const DEFAULT_INTENSITY = 0.3;
// 用户说"稍微不开心"和"我崩溃了"效果相同
```

**问题 3：VAD 跳变无平滑**

一次 `applyEvent({user_sad, intensity:0.3})` 使 VAD 在 1ms 内从 `(0.5,0.5,0.5)` 跳到 `(0.08,0.3,0.3)`，Live2D 表情无法平滑过渡。

**问题 4：无混合情绪支持**

`vadToEmotion()` 始终返回最近邻单点，无法表达"又气又好笑"(angry+happy) 的混合状态。

**问题 5：人格特质过于简化**

仅 2 个特质（empathy × valence、playfulness × arousal），缺少大五人格中对 baseline offset（外向性→V 基线向上）、噪声抑制（尽责性→D 稳定）、增益放大（神经质→敏感度）的关键调制能力。

### 1.3 升级目标

从**离散点映射**升级为**概率场模型**，覆盖 4 层：

```
感知端（Layer 1）: Perceptor 关键词匹配          →   LLM 感知 + VADWithConfidence + Top3 Mixed
状态估计（Layer 2）: applyEvent 直接叠加           →   EMA 低通滤波 + 随机漫步噪声
标签映射（Layer 3）: 欧氏最近邻 → 单点返回         →   高斯 PDF 匹配 → Top-3 概率输出
人格调制（Layer 4）: 2 特质线性增益                →   大五人格调制矩阵 + 基线偏移
```

## 七、数据流（升级后 vs 当前对比）

### 7.1 当前数据流

```
用户输入 "好难过啊..."
  → Perceptor.perceive() → 正则匹配 → user_sad, intensity=0.3
  → PersonalityEngine.applyEvent()
    → emotionToVAD('sad') → (0.15, 0.30, 0.30)
    → constrainDelta(traits) → 线性增益
    → VAD 从 (0.5,0.5,0.5) 跳变到 (0.08,0.3,0.3)  ← 跳变
  → vadToEmotion((0.08,0.3,0.3)) → 'sad'  ← 单点，无不确定度
```

### 7.2 升级后数据流

```
用户输入 "好难过啊..."
  ├── [有 LLM] Perceptor.llmPerceive("好难过啊...")
  │     → { vad: (0.12, 0.28, 0.32), confidence: 0.88,
  │         mixed: [{emotion:'sad', prob:0.7}, {sorrow:0.2}, {tired:0.1}] }
  │
  └── [无 LLM] Perceptor.perceive("好难过啊...")
        → user_sad, intensity=0.3（降级路径不变）

  → PersonalityEngine.applyEvent(perception)
    → emotionToVAD('sad') → (0.15, 0.30, 0.30)
    → modulateDelta(rawDelta, BigFiveTraits)  ← 5 因子矩阵调制
    → 存入 target VAD，不直接更新 current
    → smoothTick() → current 向 target 靠近 30%  ← EMA 平滑

  → ProbabilityDensityMatcher.match(smoothedVAD)
    → 高斯 PDF 评分 → Top-3:
      [{emotion:'sad', prob:0.65}, {sorrow:0.25}, {tired:0.08}, ...]

  → Expresser 输出:
    emotionUpdate: {
      emotion: 'sad',       ← 仍是主情绪
      mixedEmotions: [      ← 新增混合概率
        {emotion: 'sad', probability: 0.65},
        {emotion: 'sorrow', probability: 0.25},
        {emotion: 'tired', probability: 0.08}
      ]
    }
```

## 八、降级策略

| 场景 | 降级路径 | 行为 |
|:----|:---------|:-----|
| LLM 不可用时 | `llmPerceive()` → 抛出/超时 → 自动降级 `perceive()` | 保持现有正则匹配能力，无 VADWithConfidence |
| 高斯 PDF 初始化失败 | `ProbabilityDensityMatcher` 构造异常 → 降级 `vadToEmotion()` 最近邻 | 回到当前行为 |
| 大五人格配置缺失 | `BigFiveTraits` 中部分字段未配置 → 使用 DEFAULT_TRAITS 中的 0.5 默认值 | 新特质默认 0.5（中性）不影响现有行为 |
| EMA 平滑因子越界 | `smoothingFactor < 0.05 或 > 1.0` → clamp 到合法范围 | 静默修复 |

# 🏛️ 架构方案选择记录 (ADR) — 用户叙事与动态画像系统

**版本**: v1.0.0-draft | **日期**: 2026-07-10 | **状态**: 草稿

## 1. 需求背景

在情感计算（VAD 模型 + PersonalityEngine）的基础上，将 livedesign 从"建模用户以优化响应"升级为"与用户共同成长"。核心转变：

- **从静态标签画像**（MBTI/大五人格） → **动态叙事档案**（随时间展开的观察记录）
- **从策略性共情**（为维持使用） → **真实共情的累积**（希望用户成为更好的自己）
- **从优化会话满意度** → **促进用户长期福祉**

## 2. 三大候选方案对比

| 维度 | 方案A（极简运维） | 方案B（均衡架构）⬅️ **选定** | 方案C（高扩展） |
|:-----|:------------------|:---------------------------|:----------------|
| **核心思路** | JSON 文件存储 + Node.js 定时脚本 | SQLite + 内嵌调度器 + LLM 反思 Agent | 事件总线 + 独立叙事微服务 |
| **Layer 1 存储** | JSON 文件按日期分片 | SQLite 三表（observations/quantitative/hypotheses） | PostgreSQL + 事件溯源 |
| **Layer 2 量化** | setInterval + JSON 输出 | node-schedule 定时 + 数据库视图 | 独立 Worker + 流式计算 |
| **Layer 3 反思** | 手动触发 LLM | 反思 Agent 定时批处理 + 自动合并假设 | 反思 Agent 横向扩展 |
| **Layer 4 画像** | 手写合并 L2+L3 | ProfileMerger 自动合成，BlessStar Schema 管理 | Pub/Sub 实时推送 |

| **配置治理深度** | 无 | 中（BlessStar Schema + 门禁，8 字段） | 深（Schema + 事件驱动） |

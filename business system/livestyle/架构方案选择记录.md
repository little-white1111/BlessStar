## 1. 需求背景

### 1.1 业务描述

**livestyle** 是一个面向直播主播和 OBS 用户的**直播间样式可视化设计器**。用户通过拖拽、缩放等可视化操作，在画布上自由排列和配置直播间组件（弹幕列表、背景、音乐歌词、打赏动画等），实时预览效果，并通过 obs-websocket 将配置推送到 OBS，或导出配置文件供 OBS 独立加载。

### 1.2 核心功能清单

| # | 功能 | 描述 | 优先级 |
|:-|:-----|:-----|:------:|
| F1 | 可视化画布编辑器 | 基于 React 的拖拽/缩放/自由布局画布 | P0 |
| F2 | 组件化样式系统 | 弹幕列表、背景、音乐歌词等组件，可独立开发、可插拔加载 | P0 |
| F3 | 图层管理 | PS 式图层层级（z-index）、显隐切换、锁定 | P0 |
| F4 | 属性面板 | 选中组件后配置其样式参数（颜色、字体、位置、动画等） | P0 |
| F5 | OBS 集成 | 双向：实时通过 obs-websocket 推送配置 + 导出文件供 OBS 读取 | P1 |
| F6 | 组件配置本地存储 | 存放在 `~/livestyle/components/` 目录，每个组件一个配置文件 | P1 |

### 1.3 非功能性需求

| 类型 | 需求 | 约束 |
|:-----|:-----|:-----|
| 性能 | 无组件数量限制，画布需实时渲染 | WebGL/Canvas 加速，虚拟列表/脏矩形 |
| 热更新 | 运行时热更新，不刷新页面即可调整配置 | 文件监听 → 配置变更 → 实时生效 |
| 架构 | 纯前端应用 + 本地文件系统存储 | 无后端服务，Electron/Web 均可 |
| 配置 | 走 BlessStar 配置加载链路（Phase 2 接入） | Schema 验证 + 文件监听热更新 |
| 团队 | 单人开发 | 架构需简洁，减少认知负荷 |
| 阶段 | Phase 1 — 核心骨架 | 配置字段暂未确定，留待 Phase 2 configdesigner 提取 |

## 2. 三大候选方案对比

| 维度 | 方案A（极简运维） | 方案B（均衡架构）⬅️ **已选定** | 方案C（高扩展） |
|:-----|:------------------|:---------------------------|:----------------|
| **核心思路** | 单体 React 应用，所有功能内聚，直接操作文件系统 | 分层模块化，编辑器与组件引擎分离，BlessStar 管理配置 | 微前端 + 插件沙箱，事件总线解耦，多渲染目标 |

## 3. 选定方案论证

### 选定方案B（均衡架构）的理由

1. **模块边界化解耦合**：livestyle 的核心矛盾在于"画布编辑器"与"组件运行时引擎"的生命周期不同——画布需要高频交互事件（拖拽/缩放/选中），组件引擎需要高效渲染（实时视频/动画）。方案A 将两者耦合在一起，当组件数量增加时必然出现渲染卡顿。方案B 通过 Web Components 包装层将两者解耦，组件引擎独立运行，不受 React 重渲染影响。

2. **BlessStar 配置管理是刚需**：用户的非功能性需求明确要求"走 BlessStar 配置加载链路（Schema 验证 + 文件监听热更新）"。方案A 无法满足此需求，方案C 又引入过多配置治理能力（门禁、降级、事件触发），对于 Phase 1 的单人团队而言过度了。方案B 恰好匹配——Phase 1 预留位置，Phase 2 接入 BlessStar。

3. **Web Components 包装层提供框架无关性**：直播间组件可能由不同开发者使用不同框架编写（React/Vue/原生 JS）。方案B 的 Web Components 包装层提供了框架无关的组件加载能力，同时为未来的组件市场/插件生态奠定基础。

4. **单人团队友好**：方案B 的 4 个模块（editor/engine/plugin-sdk/obs-bridge）的边界恰好对应 4 个独立关注点，单人开发可依次推进（先 editor+engine，再 plugin-sdk，最后 obs-bridge），每个阶段都有可交付成果。

### 技术决策汇总

| 决策点 | 选择 | 理由 |
|:-------|:-----|:------|
| 编辑器框架 | React + TypeScript | 用户明确要求 |
| 画布引擎 | fabric.js | 社区活跃，SVG+Canvas 双模式，适合设计器场景 |
| 状态管理 | Zustand（轻量） | 比 Redux 简单，比 Context 高效，适合单人团队 |
| 组件加载 | Web Components 包装 | 框架无关，支持未来生态 |
| 编辑器引擎通信 | 自定义事件 (CustomEvent) | 原生支持，无额外依赖，适合 Web Components 生态 |
| 引擎隔离方式 | Worker / iframe | 独立执行上下文，避免 React 重渲染干扰 |
| 配置管理 | BlessStar Schema + 文件监听（Phase 2） | 满足 NFR，Phase 1 预留位置 |
| OBS 集成 | 独立 obs-bridge 模块 | 与编辑器逻辑解耦，故障不传播 |
| 本地存储 | ~/livestyle/components/ 每组件独立文件 | 明确指定 |
| Plugin SDK | 零依赖打包 | 降低组件开发者门槛，无需安装 React |

## 5. 架构不变量（审查红线）

以下为架构级不可妥协的规则，任何代码变更不得违反：

| # | 不变量 | 严重度 | 说明 | 验证方式 |
|:-:|:-------|:------:|:------|:---------|
| I1 | **画布编辑器与组件运行时引擎必须运行在独立的执行上下文中** | 🔴 红线 | 编辑器（React 重渲染循环）与组件引擎（实时渲染循环）共享同一线程会导致帧率下降。必须通过 Worker / iframe / 子进程隔离。 | 性能测试：10 个组件同时存在时，画布拖拽帧率 ≥ 30fps |
| I2 | **组件配置变更必须经过 BlessStar Schema 验证（Phase 2 生效）** | 🔴 红线 | 任何写入 `~/livestyle/components/` 的 YAML 文件必须先经 Schema 校验，拒绝非法配置。不允许绕过验证直接写文件。Phase 1 使用本地 JSON 直读占位。 | 集成测试：写入非法字段 → 验证被拒绝 |
| I3 | **组件必须通过 Web Components 标准接口加载** | 🟡 重要 | 所有组件必须实现标准的 Web Components 生命周期（`connectedCallback` / `disconnectedCallback` / `attributeChangedCallback`），不得直接依赖 React 生命周期。 | 类型测试：验证每个组件注册为 `customElements.define()` |
| I4 | **组件配置以独立文件存储，不汇聚为单一配置文件** | 🟡 重要 | 每个组件的配置存储在 `~/livestyle/components/<name>/component.yaml`，不得将所有组件配置合并写入一个文件。 | 架构测试：验证写操作路径格式 |
| I5 | **OBS 集成必须是可选的，不得阻塞编辑器主流程** | 🔴 红线 | OBS 连接失败/不可用不应影响画布编辑功能。obs-bridge 模块的故障不得传播到编辑器或组件引擎。 | 故障注入测试：断开 OBS → 验证编辑器正常操作 |
| I6 | **文件变更（外部编辑）必须触发组件热更新** | 🟡 重要 | BlessStar 文件监听检测到 `component.yaml` 变更后，必须重新验证 Schema 并通知 ComponentEngine 更新渲染。Phase 1 实现简易文件轮询。 | 集成测试：外部修改文件 → 验证组件自动重渲染 |
| I7 | **禁止组件间直接耦合通信** | 🔴 红线 | 组件之间不得通过 import/引用直接调用。必须通过 ComponentEngine 的 EventBus 或配置变更间接通信。 | 架构测试：静态分析 import 路径 |
| I8 | **组件 SDK（plugin-sdk）必须零依赖打包** | 🟡 重要 | `livestyle-plugin-sdk/` 导出的类型和工具函数不得依赖 React 或任何 UI 框架，仅依赖原生 Web API + TypeScript。 | 构建测试：验证 SDK 的 bundle 中无 React |
| I9 | **图层管理与渲染顺序必须解耦** | 🟡 重要 | 图层的 z-index/显隐/锁定状态由编辑器侧的 LayerManager 维护，组件引擎只消费最终的排序和可见性列表，不持有图层逻辑。 | 单元测试：验证 engine 无 LayerManager 引用 |
| I10 | **配置导出格式必须版本化** | 🔴 红线 | 所有导出的 OBS 配置文件和组件配置文件必须携带 `version` 字段，支持向前兼容读取旧版本格式。 | 兼容性测试：加载 v1.0 格式 → 验证可正常解析 |
| I11 | **单向数据流：编辑器 → ComponentEngine → 组件实例** | 🟡 重要 | 状态变更方向：编辑器 →（通过 IPC）→ ComponentEngine →（通过属性赋值）→ Web Components 实例。不允许组件实例直接修改编辑器状态。 | 架构测试：验证组件实例无 store 引用 |

```typescript
// Phase 1 占位实现（本地 JSON 文件直读）

class ConfigManagerPhase1 {
  private configDir: string;

  constructor(baseDir: string) {
    this.configDir = path.join(baseDir, 'components');
  }

  get(componentId: string): ConfigObject {
    const filePath = path.join(this.configDir, componentId, 'component.yaml');
    return yaml.parse(fs.readFileSync(filePath, 'utf-8'));
  }

  set(componentId: string, config: ConfigObject): void {
    const filePath = path.join(this.configDir, componentId, 'component.yaml');
    fs.writeFileSync(filePath, yaml.stringify(config));
  }
}
```

## 9. 降级策略

| 场景 | 降级路径 | 行为 |
|:-----|:---------|:-----|
| BlessStar Sidecar 不可用（Phase 2） | ConfigManager 降级到本地 JSON 直读 | 失去 Schema 验证和热更新能力，但基础编辑功能正常 |
| OBS 连接失败 | obs-bridge 进入 disconnected 状态，定时重连 | 编辑器正常，OBS 推送按钮禁用，显示断连提示 |
| 组件引擎 Worker 崩溃 | 自动重启 Worker，编辑器显示"组件引擎重启中" | 编辑器 UI 不受影响，组件配置等待引擎恢复后同步 |
| 单个组件加载失败 | ComponentRegistry 跳过该组件，其余组件正常 | 编辑器跳过该组件注册，显示占位符"组件加载失败" |
| Schema 验证失败（Phase 2） | 写操作被拒绝，编辑器显示验证错误详情 | 配置不写入文件，用户根据错误提示修正后重试 |

## 2. 方向1：编辑器完整架构（三面板 + 组件画板）

### 2.1 总体设计原则

1. **Store 层拆分** — 将 Phase 1 单一的 `editorStore` 拆分为多个独立 Store，按关注点分离
2. **组件画板独立渲染上下文** — ComponentCanvas 运行在 iframe 中，使用独立的 Zustand 实例
3. **数据同步** — 组件画板与主画布通过 engineClient IPC 同步，不直接共享 Store
4. **字段渲染器插件化** — PropsPanel 中的字段类型渲染器可注册扩展

#### 2.3.4 组件画板 (ComponentCanvas)

**设计要点：**

2. **两种模式** — 编辑模式（拖拽内部元素布局）和预览模式（加载真实数据渲染）
3. **数据同步** — 通过 engineClient（方向2的 TransportAdapter）与主画布通信

**编辑模式 vs 预览模式：**

| 维度 | 编辑模式 | 预览模式 |
|:-----|:---------|:---------|
| 交互 | 拖拽内部元素、调整布局 | 只读，模拟真实直播场景 |
| 数据 | 使用默认/占位数据 | 加载真实数据源 |
| 渲染 | 显示辅助线/网格/对齐标记 | 纯净渲染，无辅助元素 |
| 性能要求 | 中等 | 高（模拟真实性能） |
| 更新方式 | 用户操作 → 实时更新 | 接收引擎推送 → 更新 |

**减少主进程渲染压力的实现策略：**

1. iframe 使用 `sandbox` 属性限制权限：`sandbox="allow-scripts allow-same-origin"`
2. iframe 内运行独立的 Zustand 实例，不与主 Store 共享
3. 组件画板内的交互事件通过 `postMessage` 传递，不涉及主画布的 fabric.js 重渲染
4. 主画布中选中组件时，组件画板异步加载，不阻塞主线程

#### 3.1.2 三种实现

```typescript
// transport/PostMessageAdapter.ts
/**
 * iframe postMessage 传输适配器
 * 主方案 — 用于浏览器环境
 */
export class PostMessageAdapter implements TransportAdapter {
  private iframe: HTMLIFrameElement | null = null;
  private targetWindow: Window | null = null;
  private handler: ((message: string) => void) | null = null;
  private _connected = false;
  private config: TransportAdapterConfig;
  private messageQueue: string[] = [];

  constructor(config: TransportAdapterConfig) {
    this.config = config;
  }

  async connect(): Promise<void> {
    // 创建隐藏 iframe
    this.iframe = document.createElement('iframe');
    this.iframe.src = this.config.targetUrl;
    this.iframe.style.display = 'none';

    return new Promise((resolve, reject) => {
      const timeout = setTimeout(() => {
        reject(new Error('[PostMessageAdapter] Connection timeout'));
      }, this.config.timeoutMs || 10000);

      this.iframe!.onload = () => {
        this.targetWindow = this.iframe!.contentWindow;
        this._connected = true;
        clearTimeout(timeout);

        // 监听消息
        window.addEventListener('message', this.handleMessageEvent);

        // 发送队列中的消息
        while (this.messageQueue.length > 0) {
          this.send(this.messageQueue.shift()!);
        }

        resolve();
      };

      document.body.appendChild(this.iframe);
    });
  }

  send(message: string): void {
    if (!this._connected || !this.targetWindow) {
      this.messageQueue.push(message);
      return;
    }
    this.targetWindow.postMessage(message, this.config.targetOrigin || '*');
  }

  onMessage(handler: (message: string) => void): void {
    this.handler = handler;
  }

  disconnect(): void {
    this._connected = false;
    window.removeEventListener('message', this.handleMessageEvent);
    if (this.iframe && this.iframe.parentNode) {
      this.iframe.parentNode.removeChild(this.iframe);
    }
    this.iframe = null;
    this.targetWindow = null;
  }

  get connected(): boolean {
    return this._connected;
  }

  private handleMessageEvent = (event: MessageEvent): void => {
    // 验证消息来源
    if (this.config.targetOrigin !== '*' &&
        event.origin !== this.config.targetOrigin) {
      return;
    }
    if (typeof event.data === 'string' && this.handler) {
      this.handler(event.data);
    }
  };
}
```

### 3.2 engineClient 重构

Phase 1 的 `engineClient.ts` 直接创建 iframe 并与 `EditorBridge` 直接序列化消息。Phase 2 重构为：

```typescript
// services/engineClient.ts — Phase 2 重构版
import { createTransportAdapter, TransportType } from '../transport/createTransportAdapter';
import { BridgeProtocol } from '../../livestyle-engine/src/bridge/BridgeProtocol';
import { BridgeMessageType } from '../../livestyle-engine/src/types/protocol';

export class EngineClient {
  private adapter: TransportAdapter;
  private pendingRequests = new Map<string, {
    resolve: (value: unknown) => void;
    reject: (err: Error) => void;
    timer: ReturnType<typeof setTimeout>;
  }>();
  private listeners = new Map<string, Set<(payload: unknown) => void>>();

  /** 默认超时 10s */
  private readonly DEFAULT_TIMEOUT = 10000;

  constructor(transportType: TransportType, targetUrl: string) {
    this.adapter = createTransportAdapter(transportType, {
      targetUrl,
      targetOrigin: window.location.origin,
      timeoutMs: this.DEFAULT_TIMEOUT,
    });

    this.adapter.onMessage((raw: string) => {
      const message = BridgeProtocol.deserialize(raw);
      if (!message) return;
      this.handleMessage(message);
    });
  }

  async connect(): Promise<void> {
    await this.adapter.connect();
  }

  disconnect(): void {
    this.adapter.disconnect();
    // 拒绝所有待处理的请求
    for (const [, pending] of this.pendingRequests) {
      clearTimeout(pending.timer);
      pending.reject(new Error('EngineClient disconnected'));
    }
    this.pendingRequests.clear();
    this.listeners.clear();
  }

  // ========== 业务 API ==========

  async setComponentConfig(
    componentId: string,
    props: Record<string, unknown>,
  ): Promise<void> {
    const msg = BridgeProtocol.buildEditorMessage(
      BridgeMessageType.SET_COMPONENT_CONFIG,
      { componentId, props },
    );
    await this.sendAndWait(msg);
  }

  async loadComponent(
    componentId: string,
    tagName: string,
    jsUrl: string,
  ): Promise<void> {
    const msg = BridgeProtocol.buildEditorMessage(
      BridgeMessageType.LOAD_COMPONENT,
      { componentId, tagName, jsUrl },
    );
    await this.sendAndWait(msg);
  }

  async syncLayerOrder(layerOrder: LayerOrderItem[]): Promise<void> {
    const msg = BridgeProtocol.buildEditorMessage(
      BridgeMessageType.SET_LAYER_ORDER,
      { layerOrder },
    );
    await this.sendAndWait(msg);
  }

  /** 订阅引擎事件 */
  on(event: string, handler: (payload: unknown) => void): () => void {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set());
    }
    this.listeners.get(event)!.add(handler);
    return () => this.listeners.get(event)?.delete(handler);
  }

  /** 监听引擎就绪 */
  onReady(handler: () => void): () => void {
    return this.on('engineReady', handler);
  }

  /** 获取连接状态 */
  get connected(): boolean {
    return this.adapter.connected;
  }

  // ========== 内部 ==========

  private async sendAndWait(message: BridgeMessage): Promise<void> {
    return new Promise((resolve, reject) => {
      const timer = setTimeout(() => {
        this.pendingRequests.delete(message.id);
        reject(new Error(`Bridge timeout: ${message.type}`));
      }, this.DEFAULT_TIMEOUT);

      this.pendingRequests.set(message.id, {
        resolve: () => {
          clearTimeout(timer);
          resolve();
        },
        reject: (err) => {
          clearTimeout(timer);
          reject(err);
        },
        timer,
      });

      const serialized = BridgeProtocol.serialize(message);
      this.adapter.send(serialized);
    });
  }

  private handleMessage(message: BridgeMessage): void {
    // 处理 Request/Response
    const pending = this.pendingRequests.get(message.id);
    if (pending) {
      this.pendingRequests.delete(message.id);
      if (message.type === BridgeMessageType.COMPONENT_ERROR) {
        pending.reject(new Error(String((message as any).payload?.error || 'Unknown error')));
      } else {
        pending.resolve();
      }
      return;
    }

    // 处理事件推送
    const handlers = this.listeners.get(message.type);
    if (handlers) {
      handlers.forEach((handler) => handler((message as any).payload));
    }
  }
}
```

```html
        // 创建实例
        const entry = registry.getEntryById(componentId);
        if (entry) {
          const instance = new ComponentInstance(componentId, entry);
          instances.set(componentId, instance);
          sendResponse(message.id, { success: true });
        }
      } catch (err) {
        sendResponse(message.id, { success: false, error: err.message });
      }
    }

    function handleSetComponentConfig(payload) {
      const { componentId, props } = payload;
      const instance = instances.get(componentId);
      if (instance) {
        instance.update(props);
      }
      sendResponse(message.id, { success: true });
    }

    function handleSetLayerOrder(payload) {
      const { layerOrder } = payload;
      // 更新各实例的 z-index / visible
      layerOrder.forEach((item) => {
        const instance = instances.get(item.componentId);
        if (instance) {
          const el = instance.getDOMElement();
          if (el) {
            el.style.zIndex = String(item.zIndex);
            el.style.display = item.visible ? 'block' : 'none';
            el.style.pointerEvents = item.locked ? 'none' : 'auto';
          }
        }
      });
      sendResponse(message.id, { success: true });
    }

    // ========== 4. 响应发送 ==========
    function sendResponse(messageId, payload) {
      parent.postMessage(JSON.stringify({
        id: messageId,
        type: 'response',
        direction: 'engine→editor',
        payload,
        timestamp: Date.now(),
      }), '*');
    }

    // ========== 5. 事件推送 ==========
    // 组件状态变更 → 推送给编辑器
    eventBus.on('*', (eventName, data) => {
      parent.postMessage(JSON.stringify({
        id: `evt_${Date.now()}`,
        type: eventName,
        direction: 'engine→editor',
        payload: data,
        timestamp: Date.now(),
      }), '*');
    });

    // ========== 6. 通知就绪 ==========
    parent.postMessage(JSON.stringify({
      id: 'ready',
      type: 'engineReady',
      direction: 'engine→editor',
      payload: { version: '0.2.0' },
      timestamp: Date.now(),
    }), '*');

    console.log('[EngineBridge] Phase 2 — Fully initialized');
  })();
</script>
</body>
</html>
```

```typescript
// 引擎侧统一错误处理
class EngineBridgeErrorHandler {
  private maxRetries = 3;
  private retryDelay = 1000;

  async withRetry<T>(fn: () => Promise<T>, context: string): Promise<T> {
    let lastError: Error | null = null;
    for (let i = 0; i < this.maxRetries; i++) {
      try {
        return await fn();
      } catch (err) {
        lastError = err instanceof Error ? err : new Error(String(err));
        console.warn(`[EngineBridge] Retry ${i + 1}/${this.maxRetries}: ${context}`, err);
        if (i < this.maxRetries - 1) {
          await new Promise(r => setTimeout(r, this.retryDelay * (i + 1)));
        }
      }
    }
    throw lastError;
  }
}
```

```typescript
export function renderTaskList(props: Record<string, unknown>): string {

    .map((item: string) => item.trim())

  const taskListHtml = taskItems

        <div class="task-item" style="
          display: flex;
          align-items: center;
          gap: 8px;
          padding: 6px 0;

            font-size: ${fontSize}px;
```

  private pollTimer: ReturnType<typeof setInterval> | null = null;

  constructor(private options: LocalFileAdapterOptions) {
    this.loadConfig();
    if (options.pollIntervalMs && options.pollIntervalMs > 0) {
      this.startPolling(options.pollIntervalMs);
    }
  }

  get(): LivestyleConfig;
  get(key: ConfigKey): unknown;
  get(key?: unknown): LivestyleConfig | unknown {
    if (typeof key === 'string') {
      return this.getByKey(key as ConfigKey);
    }
    return { ...this.config };
  }

  async set(config: Partial<LivestyleConfig>): Promise<ValidationResult>;
  async set(key: ConfigKey, value: unknown): Promise<ValidationResult>;
  async set(keyOrConfig: unknown, value?: unknown): Promise<ValidationResult> {
    // 验证 → 写入 → 通知
    const validation = this.validate(keyOrConfig as any);
    if (!validation.valid) return validation;
    // ... 写入逻辑
    return { valid: true };
  }

  watch(callback: WatchCallback): UnwatchFn;
  watch(key: ConfigKey, callback: WatchCallback): UnwatchFn;
  watch(keyOrCallback: unknown, callback?: WatchCallback): UnwatchFn {
    const cb = callback || (keyOrCallback as WatchCallback);
    this.watchers.add(cb);
    return () => this.watchers.delete(cb);
  }

  validate(config: Partial<LivestyleConfig>): ValidationResult {
    const errors: { path: string; message: string }[] = [];
    for (const [key, meta] of Object.entries(CONFIG_FIELDS)) {
      const value = (config as any)[key];
      if (value === undefined) continue;
      if (meta.validation?.min !== undefined && value < meta.validation.min) {
        errors.push({ path: key, message: `Value ${value} < min ${meta.validation.min}` });
      }
      if (meta.validation?.max !== undefined && value > meta.validation.max) {
        errors.push({ path: key, message: `Value ${value} > max ${meta.validation.max}` });
      }
    }
    return { valid: errors.length === 0, errors: errors.length > 0 ? errors : undefined };
  }

  async reset(): Promise<void> {
    this.config = { ...DEFAULT_CONFIG };
    this.notifyWatchers({ key: '*' as any, path: '*', oldValue: null, newValue: this.config, timestamp: Date.now() });
  }

  export(): LivestyleConfig {
    return { ...this.config };
  }

  async import(config: LivestyleConfig): Promise<ValidationResult> {
    const validation = this.validate(config);
    if (!validation.valid) return validation;
    this.config = { ...config };
    return { valid: true };
  }

  private loadConfig(): void {
    // 从文件加载配置
    try {
      // const raw = fs.readFileSync(this.options.filePath, 'utf-8');
      // this.config = { ...DEFAULT_CONFIG, ...yaml.parse(raw) };
    } catch {
      this.config = { ...DEFAULT_CONFIG };
    }
  }

  private startPolling(ms: number): void {
    this.pollTimer = setInterval(() => {
      // 轮询文件变更并通知 watchers
    }, ms);
  }

  private notifyWatchers(event: ConfigChangeEvent): void {
    for (const watcher of this.watchers) {
      watcher(event);
    }
  }

  private getByKey(key: ConfigKey): unknown {
    // 根据点分隔路径访问嵌套属性
    return key.split('.').reduce((obj: any, part) => obj?.[part], this.config);
  }

```typescript
import { ConfigPort } from './__generated__/ports/ConfigPort';
import type { LivestyleConfig, ConfigKey } from './__generated__/types/config.generated';

/**
 * 配置管理器
 * Phase 2 接入 ConfigPort，替换 Phase 1 的直读实现

export class ConfigManager {
  constructor(private port: ConfigPort) {}

  /** 获取完整配置 */
  getConfig(): LivestyleConfig {
    return this.port.get();
  }

  /** 获取特定配置值 */
  get(key: ConfigKey): unknown {
    return this.port.get(key);
  }

  /** 更新配置（自动验证 → 写入 → 通知） */
  async updateConfig(partial: Partial<LivestyleConfig>): Promise<boolean> {
    const result = await this.port.set(partial);
    if (!result.valid) {
      console.error('[ConfigManager] Validation failed:', result.errors);
      return false;
    }
    return true;
  }

  watch(handler: (event: ConfigChangeEvent) => void): UnwatchFn {
    return this.port.watch(handler);
  }

  validate(config: Partial<LivestyleConfig>): ValidationResult {
    return this.port.validate(config);
  }
}
```

## 9. 决策日志

| 日期 | 决策 | 理由 |
|:-----|:-----|:------|
| 2026-07-11 | **TransportAdapter 接口从 EditorBridge 抽取为独立模块** | 支持 3 种传输方式，为 Electron Worker 和 SharedWorker 预留扩展点 |
| 2026-07-11 | **Store 拆分为 5 个独立 Zustand 实例** | 避免单 Store 膨胀（预测 Phase 2 后 editorStore 将从 180 行增长到 500+ 行），按关注点分离 |
| 2026-07-11 | **组件画板使用 iframe 隔离而非 Worker** | Worker 无法直接操作 DOM，而组件画板需要渲染完整的 Web Components；iframe 可加载完整的精简引擎实例 |
| 2026-07-11 | **属性推送使用 300ms 防抖** | 拖拽滑块等高频操作需合并，平衡实时反馈与渲染性能 |
| 2026-07-11 | **Codegen 使用 EJS 模板而非 AST 操作** | 单人团队，模板更直观易维护，且输出格式可控 |
| 2026-07-11 | **config-schema.yaml 作为唯一真理源** | 遵循 BlessStar 契约设计原则，所有 TS 类型从 Schema 生成 |
| 2026-07-11 | **组件画板与主画布通过 IPC 通信** | 遵循单向数据流不变量（I11），iframe 内 Zustand 不与主 Store 共享内存 |
| 2026-07-11 | **IPC 消息添加 PING/PONG 健康检查** | 便于检测 iframe/Worker 意外断开，触发重连机制 |
| 2026-07-11 | **Phase 2 新增 6 条架构不变量（I12-I17）** | 覆盖 Phase 2 新增模块的特殊约束 |

# 🏛️ 架构方案选择记录 (ADR) — monoplayer

> **版本**: v1.0.0 | **日期**: 2026-07-11 | **状态**: 已确认

## 1. 需求背景

开发 **monoplayer** — 基于 Godot 4.x 的 3D 模型→2D 动画视频渲染播放器。核心能力：将 3D GLTF/GLB 角色模型在固定正交相机下播放骨骼动画，通过 Toon Shader 渲染出类 Live2D 赛璐璐风格，并输出为 AVI 视频或透明 PNG 序列。

**核心功能清单**：
1. CLI 参数驱动（动画名、时长、分辨率、帧率等）
2. 固定正交相机离线渲染（相机锁死不可动）
3. 3D 骨骼动画 + 浮点参数表情控制（模拟 Live2D Param）
4. 双输出模式（AVI 直出 / 透明 PNG 序列合成）
5. 渲染失败重试（最多 3 次）
6. 自动退出（动画播放完毕关闭）

**非功能性需求**：
- 性能：~60fps @ 1080P，单任务批处理
- 可用性：渲染失败重试，配置热更新
- 部署：Windows 单机 EXE
- 扩展性：先单播放器，后续考虑引擎化集成

## 2. 三大候选方案对比

| 维度 | 方案A（极简运维） | 方案B（均衡架构）⬅️ **已选** | 方案C（高扩展） |
|:-----|:-----------------|:---------------------------|:----------------|
| **核心思路** | 单 `Main.gd` 脚本 + 命令行参数，引擎原生 MovieWriter 直出 | 分层模块化（CLI 解析层 / 渲染引擎层 / 输出适配器层），配置接口 + BlessStar 门禁 | 插件化引擎架构，事件总线驱动渲染管线，Loader 动态加载模型/输出格式 |
| **优点** | 最快落地，一个脚本搞定，依赖最少 | 关注点分离，配置热更新，输出格式可插拔，故障隔离 | 未来可直接转型为引擎被外部集成，无限扩展输出/模型格式 |
| **缺点** | 所有逻辑耦合，加功能必改核心脚本，无法热更新 | 需额外设计接口层，初始工作量比 A 大 30% | 过度设计，单人项目前期成本高，事件总线增加调试复杂度 |
| **配置治理深度** | 无（环境变量/硬编码） | 中等（Schema + 门禁 + 热更新） | 深（契约驱动 + 事件总线 + 插件注册中心） |
| **预估单任务吞吐** | ~60fps @ 1080P | ~60fps @ 1080P | ~55fps @ 1080P（事件分发开销） |
| **维护成本** | ⭐（一人维护） | ⭐⭐（结构清晰易维护） | ⭐⭐⭐（需维护插件契约） |
| **适用场景** | 个人一次性工具 | **生产级单机播放器 + 配置热更新** | 未来多格式引擎化 |

### ⚙️ 架构不变量（审查红线）

1. **相机锁定不可违反** — 运行时任何模块/插件不得修改 `Camera3D` 的投影矩阵、位置、旋转，必须通过 `FixedCamGuardian` 单例强制执行
2. **渲染管线与 CLI 生命周期绑定** — 渲染开始后 CLI 参数不可变，渲染结束前禁止提前退出
3. **输出格式与主渲染逻辑隔离** — 新增输出格式（如 WebM、RTMP 流）不得修改 `_process()` 渲染主循环代码
4. **配置变更必须在下一帧生效**（热更新语义）— 配置更新后不能残留上一帧的旧参数
5. **禁止 GPU 资源泄漏** — 每批次渲染完成后必须释放 `RenderTexture`、`Image` 等 GPU 资源
6. **失败重试不可无限循环** — 渲染失败最多重试 3 次，超过则跳过并记录错误
7. **配置端口桩必须有生产默认值** — 所有从配置中心读取的参数必须在代码中保留 fallback 默认值，确保配置中心不可用时播放器仍可按默认参数工作
8. **表情过渡不可突变** — 所有表情切换必须通过 smoothstep 插值完成（持续 ≥ 1 帧），禁止直接设置 Shader Uniform 跳过过渡
9. **队列消费不可回退** — ExpressionController 消费队列元素后必须从队列中移除，禁止重复消费
10. **GPU 插值优先** — 表情参数过渡必须在 GPU Shader 中完成（通过 uniform 递增），禁止在 CPU GDScript 中逐帧修改材质再上传

#### 🧠 表情控制模块 (expression)

**设计思路**：BlessStar 充当"表情通知器"角色，不做高频驱动。BlessStar 检测到配置变更（如 expression.queue 从 [] 变为 ['happy']）→ 通知 ExpressionController → 加入队列 → 在 GPU Shader 中通过 smoothstep 插值完成丝滑过渡。

**模块构成**：
- `internal/expression/ExpressionPort.gd` — 端口接口，声明 bind_material / on_config_changed / enqueue_expression
- `internal/expression/ExpressionController.gd` — 核心控制器：队列管理 + smoothstep 插值 + Shader uniform 同步
- `internal/expression/ExpressionNotifier.gd` — BlessStar ↔ ExpressionController 桥接层，监听配置文件变更

**数据流**：
```
BlessStar (file watcher / polling)
    │  检测到 monoplayer.expression.queue 变更
    ▼
ExpressionNotifier.on_config_changed(queue_name, raw_json)
    │  解析 JSON: ["happy", "surprised"]
    ▼
ExpressionController._enqueue_expression("happy", preset_values)
    │  追加到队列尾部
    ▼
_process(delta):
    │  transition_progress += delta / transition_duration
    │  current_values[key] = lerp(current_values[key], target_values[key], smoothstep(progress))
    │  过渡完成 → 消费队列下一个
    ▼
_sync_shader_uniforms():
    │  material.set_shader_parameter("expr_blush", 0.3)
    │  material.set_shader_parameter("expr_eye_openness", 1.0)
    ▼
Toon Shader (GPU):
    │  uniform float expr_blush;
    │  uniform float expr_eye_openness;
    │  (插值在 GPU 中完成，不消耗 CPU)
```

**配置字段**（7 个，已纳入 config-schema.yaml）：
| 字段 | 类型 | 默认值 | 说明 |
|:-----|:-----|:-------|:-----|
| expression.neutral | STR(JSON) | blush=0, eye_openness=1, mouth_blend=0, brow_angle=0 | 中立表情预设 |
| expression.happy | STR(JSON) | blush=0.3, eye_openness=1, mouth_blend=0, brow_angle=-0.2 | 开心表情预设 |
| expression.sad | STR(JSON) | blush=0, eye_openness=0.8, mouth_blend=0.7, brow_angle=0.3 | 难过表情预设 |
| expression.angry | STR(JSON) | blush=0.1, eye_openness=0.9, mouth_blend=0.3, brow_angle=0.6 | 生气表情预设 |
| expression.surprised | STR(JSON) | blush=0, eye_openness=1, mouth_blend=0.9, brow_angle=-0.5 | 惊讶表情预设 |
| expression.queue | STR(JSON) | [] | 表情播放队列 |
| expression.transition_duration | F64 | 0.3s | 过渡平滑时长 |

**不变量追加**：
8. **表情过渡不可突变** — 所有表情切换必须通过 smoothstep 插值完成（持续 ≥ 1 帧），禁止直接设置 Shader Uniform 跳过过渡
9. **队列消费不可回退** — ExpressionController 消费队列元素后必须从队列中移除，禁止重复消费
10. **GPU 插值优先** — 表情参数过渡必须在 GPU Shader 中完成（通过 uniform 递增），禁止在 CPU GDScript 中逐帧修改材质再上传

#### 输出工作流说明

```
output.format = prores  (★ 主路径，推荐):
  3D 角色 (RGBA 透明底)
    → [compositor.enabled=false] FFmpeg pipe → ProRes 4444 .mov
    → 带 Alpha 透明通道，视觉无损
    → 可直接拖入 AE / Premiere / Final Cut 使用
    → 单文件输出，无 PNG 序列的磁盘 IO 瓶颈
    → 格式参数: output.prores_quality = 4444/4444XQ/422HQ/422

output.format = avi (备选，快速预览):
  3D 角色 → 叠加背景板 → 合成帧 → Godot MovieWriter → .avi
  → output.compositor.enabled=true 建议配合使用
  → 无透明通道，但编码最快（适合调试/批量预渲）

output.format = prores + compositor.enabled = true (特殊场景):
  叠加背景板后输出 ProRes .mov（背景不是透明而是棋盘格）
  → 适合在不支持透明的播放器中预览"透明效果"
```

#### 门禁规则摘要（共 40 条）

| 规则类型 | 数量 | 示例 |
|:---------|:-----|:------|
| **RANGE** | 19 | `orthogonal_size` 必须在 0.1~50.0；`plate_scale` 必须在 0.1~10.0 |
| **DEPENDENCY** | 2 | `width / height ≈ 目标宽高比` |
| **SLO_WARNING** | 19 | `bloom_intensity` 接近 5.0 时告警；`plate_opacity` 接近 1.0 时告警 |

> ProRes 相关字段（format / prores_quality / prores_output_path）为 STR 枚举类型，无 range/slo_impact 契约，不生成门禁规则。

### 🚀 落地步骤

1. **创建 Godot 项目骨架**
   ```
   mkdir monoplayer && cd monoplayer
   godot --editor  # 创建 project.godot
   ```
   按模块拆分创建 `cmd/`、`internal/`、`Scenes/`、`Shaders/` 目录结构

2. **实现核心编排层**
   - `cmd/main.gd`：CLI 参数解析（`OS.get_cmdline_user_args()`）
   - `internal/pipeline/RenderPipeline.gd`：`_process()` 渲染主循环

3. **实现 FixedCamGuardian**（架构不变量 #1）
   - 单例模式锁死 Camera3D 变换
   - `set_process(false)` 禁止运行时代码修改

4. **实现 OutputPort 适配器层**
   - `internal/output/adapters/ProResExporter.gd` — ★ ProRes 4444 .mov 主路径（FFmpeg pipe 编码）
   - `internal/output/adapters/MovieWriter.gd` — AVI 快速预览（无透明）
   - `internal/output/adapters/PNGSequence.gd` — 透明 PNG 序列（旧路径兼容）

5. **实现 LightingController**
   - `internal/lighting/LightController.gd` — 角度/强度/补光/轮廓光控制
   - 与 Toon Shader 联动：光源角度改变阴影方向，强度改变亮面亮度

6. **实现 PostProcess 后处理管线**
   - `internal/postprocess/adapters/ColorGrading.gd` — 色温 + 饱和度校正
   - `internal/postprocess/adapters/ContrastFilter.gd` — 对比度调节
   - `internal/postprocess/adapters/BloomFilter.gd` — 辉光效果
   - 管线串联：`_process()` → ColorGrading → Contrast → Bloom → Output Frame

7. **实现 Compositor 实时合成器**
   - `internal/compositor/BackgroundPlate.gd` — 加载背景板 PNG 并固定到相机底层
   - 场景树：Root → BackgroundPlane (Sprite3D) + CharacterRoot (Node3D)
   - 合成逻辑：角色渲染层（RGBA 透明底）叠加背景板 → 合成完整帧
   - 输出方式选择：`compositor.enabled=true` 走 AVI 直出，`=false` 走 PNG 序列

8. **实现 ConfigPort + BlessStarLoader**
   - `internal/config/adapters/FallbackConfig.gd` — 硬编码默认值回退
   - `internal/config/adapters/BlessStarLoader.gd` — 热更新监听

9. **配置 CI 流水线**（GitHub Actions）
   ```yaml
   # .github/workflows/ci.yml
   - name: 门禁校验
     run: blessstar-codegen --check --schema config-schema.yaml
   - name: GDScript 语法检查
     run: gdscript-lint ./internal/
   ```

10. **部署 SchemaLoader**
   ```
   cp config-schema.yaml /etc/blessstar/schemas/monoplayer.yaml
   ```
